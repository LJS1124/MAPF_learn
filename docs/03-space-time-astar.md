# 03 时空 A*（Space-Time A*）

## 3.1 为什么需要时间维度

单智能体 A* 的状态是位置 *v*。MAPF 中，同一格子“t=3 可以走、t=5 不能走”，所以状态必须扩展为 **(位置, 时间)**，并允许**等待**动作：

```
(v, t) → (v', t+1)  对每个邻居 v' 以及 v' = v（等待）
```

搜索空间因此变成“图 × 时间轴”。

## 3.2 约束的三种形式

`ConstraintTable` 保存单个智能体必须遵守的约束：

| 字段 | 含义 | 谁会用到 |
|---|---|---|
| `vertex {(loc,t)}` | 时刻 t 不得位于 loc | CBS、PP |
| `edge {(a,b,t)}` | 不得在 t-1 位于 a 且 t 位于 b | CBS、PP（防对穿） |
| `static {loc: t0}` | 从 t0 起 loc 永久不可用 | PP（已到终点的高优先级智能体） |

## 3.3 终止条件的陷阱

“到达终点”不等于“可以停下”。若终点在未来某时刻 *t′* 有顶点约束（别的智能体那时要经过这里），你不能在 t′ 之前就宣布完成——否则你会在 t′ 撞上。因此终止条件是：

```
loc == goal  且  t >= goal_free_time
```

`goal_free_time` = 终点上所有顶点约束时刻的最大值 + 1（`ConstraintTable.goal_free_time`）。

这是初学者实现 CBS 最常见的 bug 之一。测试 `test_goal_constraint_later_in_time` 覆盖了它。

## 3.4 其他细节

- **时间上界**：约束存在时“继续等待”可以无限展开，所以设 `max_time = 最晚约束时刻 + 空地数`，超出视为无解。
- **平局处理**：f 相同时优先 h 小（离终点近）的节点，能显著减少展开数。
- **closed 集合**存 `(loc, t)`。因为每步代价恒为 1，g = t，首次到达即最优，无需处理“更优路径”。

## 3.5 复杂度直觉

时空节点数 ≈ |V| × T。T 越大（约束越多、等待越多）搜索越慢。进阶方法 SIPP（见第 07 章）把“连续的无冲突时间段”合并成一个状态，避免逐时刻展开。

## 小结

ST-A* = A* + 时间维度 + 等待动作 + 约束表。它是 PP 与 CBS 共同的底层规划器。
