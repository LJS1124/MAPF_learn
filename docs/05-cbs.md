# 05 冲突搜索 CBS（Conflict-Based Search）

CBS（Sharon, Stern, Felner, Sturtevant, 2015）是 MAPF 最优算法的基石。思路：**不要在联合状态空间里搜索，而是在“冲突”空间里搜索。**

## 5.1 两层结构

**低层**：每个智能体独立跑时空 A*，只需遵守分配给它的约束。

**高层**：搜索一棵**约束树（CT）**。CT 节点包含：

- 每个智能体的约束集合；
- 在这些约束下各自的最优路径；
- 解的代价（SOC）。

## 5.2 流程

```
根节点：无约束，各走各的最短路
循环：
  取出 OPEN 中代价最小的 CT 节点 N
  在 N 的路径中找冲突；没有 → 返回 N.paths（最优解）
  取一个冲突 (i, j, 位置, 时刻)，分裂为两个子节点：
     子节点 1：给 i 加约束“t 时刻不得在该位置”，只重规划 i
     子节点 2：给 j 加同样约束，只重规划 j
  子节点若规划失败则丢弃，否则入 OPEN
```

## 5.3 为什么这样分裂是对的

冲突 (i, j, v, t) 表示“i 与 j 不能同时在 v”。任何合法解里，**至少有一个**不在 v@t。所以两个子节点覆盖了所有可能的合法解 → **完备**。

又因为高层按代价从小到大扩展，且低层保证每个节点的路径在约束下最优，节点代价是该分支所有解的下界 → 第一个无冲突节点**最优**。

## 5.4 边冲突的约束

冲突：i 走 a→b，j 走 b→a，到达时刻 t。约束：

- 子节点 1：i 不得在 t 时刻从 a 走到 b；
- 子节点 2：j 不得在 t 时刻从 b 走到 a。

对应 `cbs._split` 与 `ConstraintTable.add_edge`。

## 5.5 代码走读（`mapf/cbs.py`）

- `CTNode`：约束 + 路径 + 代价 + 冲突数；
- 优先队列键 `(cost, n_conflicts, 序号)`：同代价时冲突少的优先，是一个廉价但有效的平局策略；
- 子节点只复制被修改智能体的约束表，路径列表浅拷贝后只替换一条；
- `max_nodes` 防止无解或困难实例无限运行——**CBS 最坏情况指数级**，实际中要靠上限与改进变体。

## 5.6 亲手验证

`python3 examples/02_swap_conflict.py`：PP 失败，CBS 在窄走廊里找到 SOC=15：两条路径基础长度各 6，额外 1 步等待 + 一个智能体进出岔路 2 步。

`tests/test_mapf.py::test_cbs_no_worse_than_pp` 随机检查：凡 CBS 返回解，都通过 `validate`，且 SOC 不大于 PP 的解。

## 5.7 CBS 的弱点与改进

| 问题 | 改进 |
|---|---|
| 一个冲突分裂后代价可能不涨，导致大量“对称”节点 | ICBS：冲突分类（cardinal/semi/non-cardinal），优先分裂 cardinal |
| 高层需要更强的下界 | CBSH：用冲突图上的最小顶点覆盖/独立集作为启发 |
| 对称冲突（矩形/走廊） | 对称性推理 |
| 完全最优太慢 | 有界次优：ECBS、EECBS |

详见第 07 章。

## 小结

CBS = 高层在冲突上分裂，低层在约束下规划。完备、SOC 最优，但最坏情形指数级。
