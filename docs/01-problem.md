# 01 问题定义

## 1.1 一个直观例子

一条只容一辆车宽的窄走廊，两端各有一台机器人想去对面。谁都不能穿过对方，必须有人先退到岔路里让路。MAPF 就是要系统地回答“谁在什么时候让、去哪让、代价最小是多少”。

运行 `python3 examples/02_swap_conflict.py` 可以看到这个例子（地图 `maps/corridor.map`）。

## 1.2 形式化定义

一个 MAPF 实例由三部分组成：

- 一个无向图 *G = (V, E)*（本教程里是四连通栅格，障碍格不在 V 中）；
- *k* 个智能体，智能体 *i* 有起点 *s_i* 和终点 *g_i*；
- 离散时间：每个时间步，每个智能体要么**移动**到相邻顶点，要么**原地等待**。

解是 *k* 条路径 *π_i = (v_0, v_1, …, v_T)*，满足 *v_0 = s_i*、*v_T = g_i*，且两两之间无冲突。

## 1.3 冲突（Conflict）

| 类型 | 含义 | 例子 |
|---|---|---|
| 顶点冲突 | 同一时刻位于同一顶点 | A、B 在 t=3 都在 (2,3) |
| 边冲突（对穿） | 同一时刻交换位置 | A: (2,3)→(2,4)，B: (2,4)→(2,3) |
| 跟随冲突（可选） | B 移入 A 在同一步刚离开的格子 | 本教程**允许**跟随 |
| 环形旋转（可选） | 多个智能体绕圈同时前进 | 本教程**不检查**该情形 |

不同论文/系统对后两项规定不同，读论文时要先确认冲突模型。

**到达后行为**也有两种约定：智能体到达终点后**消失**，或**停留**。本教程采用“停留”，更贴近现实，也让问题更难：已到达的智能体仍然是障碍。代码里 `utils.location_at` 就是这个约定的实现。

## 1.4 目标函数

- **SOC（Sum of Costs / flowtime）**：所有智能体到达终点的时刻之和，`utils.sum_of_costs`。
- **Makespan**：最后一个智能体到达的时刻，`utils.makespan`。

两者会冲突：最小化 makespan 的解 SOC 不一定最小。CBS 优化 SOC。

## 1.5 复杂度：为什么难

- 单智能体：A* 多项式可解。
- 联合状态空间：*k* 个智能体的联合位置有 |V|^k 种，直接 A* 指数爆炸。
- 是否有解与具体冲突模型有关，某些模型下判定可以多项式完成；但**求 SOC 或 makespan 最优解是 NP-hard**（Yu & LaValle 2013 等）。本教程的代码在无解时只能靠节点上限/时间上界放弃（见 `cbs(max_nodes=...)`），并不能证明无解。

这决定了算法设计的两条路线：**最优但慢**（CBS 系）与**快速但次优**（PP、PIBT、LNS 等）。

## 1.6 对应代码

- `Grid` / `Instance`：地图与实例，`Instance.starts/goals` 下标即智能体编号。
- `random_instance`：随机实例生成（起点终点不重复，且各自连通，但整体不一定可解）。
- `validate`：**校验器**。写任何 MAPF 算法都应先写校验器——它是你唯一可靠的“标准答案”。

## 小结

MAPF = 一组互不冲突的时空路径。冲突模型、到达后行为、目标函数是三个必须先固定的“约定”。
