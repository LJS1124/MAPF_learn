## 自测题

1. 为什么 CBS 的低层要允许“等待”动作？
2. 什么情形下，PP 无论怎么排优先级都会失败，而问题有解？
3. 顶点冲突的两个约束为什么必须在两个子节点里**各加一个**，而不是在一个节点里同时加？
4. 为什么 ST-A* 到达终点还要检查 `goal_free_time`？
5. CBS 返回的解为何是 SOC 最优？如果低层不是最优（比如用了带权 A*），会怎样？

<details><summary>参考答案要点</summary>

1. 没有等待，很多约束下无解（如让路后原地不动）。
2. 窄走廊/单行道互换，高优先级者停在终点堵路（见 02_swap_conflict）。
3. 两个约束是“或”关系：合法解至少满足其一。放在同一节点就变成“两人都不能在此”，会排除合法解，丧失完备性。
4. 终点之后仍可能被别的智能体路过，不能提前“停下”。
5. 高层按下界扩展 + 低层最优。低层次优则整体只保证有界次优（这正是 ECBS 的思路）。
</details>
