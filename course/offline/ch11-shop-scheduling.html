11流水车间与作业车间：作业要走过好几台机器

前两章的作业只在一台机器（或一组相同的机器）上加工一次。实际的作业常常要依次经过好几道工序：托盘入库、上提升机、出库；一个订单要经过几个站点。这一章看两种最基本的多工序模型：所有作业走同样路线的流水车间，和每个作业路线不同的作业车间。前者在两台机器时有漂亮的规则，后者要用析取图来表示，并且从这里开始，建模方式（MIP 还是 CP）会明显影响能解多大的问题。

学完本章，你能

  1. 用递推公式算出流水车间任意顺序的 Cmax，手写 Johnson 规则解 F2 | | Cmax，并说明为什么三台以上没有这样的规则。
  2. 用 NEH 启发式解一般的流水车间，看出它为什么比随便排好，又为什么不保证最优。
  3. 把作业车间的一个调度写成析取图：选定每台机器上的作业顺序，Cmax 就是最长路，出现环就说明顺序不可行。
  4. 为同一个作业车间问题写出大 M 的 MIP 和 CP-SAT 两种模型，并解释为什么规模一大，两者差距悬殊。

11.1流水车间与 Johnson 规则

流水车间（flow shop）里有 m 台机器，每个作业都按同样的次序经过它们：先第 1 台，再第 2 台……记号是 Fm | | Cmax。作业 j 在第 k 台机器上的加工时间是 pjk。入库 → 提升机 → 出库就是一个 F3。

每台机器一次只做一个作业，一个作业同一时刻只在一台机器上。最常见的限制是置换流水车间（permutation flow shop）：所有机器上的作业顺序相同，于是决策只有一个，就是作业的排列。对 Cmax 而言，两台和三台机器时最优调度总可以取成置换的，所以下面只看排列。

给定排列，各作业在各机器上的完工时间由一个递推给出。设 Cjk 是排在第 j 位的作业在机器 k 上的完工时间：

完工时间递推Cjk = max( Cj−1,k, Cj,k−1 ) + pjk要等这台机器上一个作业做完，也要等自己在上一台机器上做完

Cmax 就是最后一个作业在最后一台机器上的完工时间。这个递推是 O(nm) 的，所以评价一个排列很便宜，难的是在 n! 个排列里找最好的。

两台机器：Johnson 规则（1954）。F2 | | Cmax 有一个多项式的最优算法。记作业 j 在两台机器上的时间为 aj、bj：

  1. 把 aj ≤ bj 的作业放进集合 1，把 aj > bj 的放进集合 2。
  2. 集合 1 按 a 从小到大排在前面，集合 2 按 b 从大到小排在后面。

直觉是两头夹：第二台机器要等第一台送来作业才能开工，所以让 a 小的作业先走，第二台机器早早有活干；最后一个作业在第二台机器上做完就结束了，所以让 b 小的作业留到最后，收尾的空转最短。证明用的是交换论证，和上一章一样：对相邻的两个作业 i、j，若 min(ai, bj) ≤ min(aj, bi)，则把 i 排在 j 前面不会更差。这个两两比较的关系是可以传递的，所以能推出整个顺序。

读图

原顺序 J1…J6：Cmax = 35。J2 在第一台机器上要 9，第二台机器在这段时间里几乎全部空着。Johnson 顺序：集合 1 是 J1、J6、J2（a 依次为 1、1、9，并列取下标小的），集合 2 是 J3、J5、J4（b 依次为 5、4、2）。得到 J1 → J6 → J2 → J3 → J5 → J4，Cmax = 31，与枚举 720 种得到的最优一致。最差顺序：41，比最优多 10。

试着把 Johnson 顺序里的两个作业交换。绝大多数交换会让 Cmax 变大或不变，不会变小。这就是最优的含义。

三台机器

F3 | | Cmax 是强 NP 难的（Garey、Johnson、Sethi，1976），所以不能指望像 Johnson 那样的规则。有一个特殊情形可以化简：若第二台机器被“压住”，即 min a ≥ max b 或 min c ≥ max b（a、b、c 是三台机器的时间），那么把每个作业合成 (a+b, b+c) 两台虚拟机器，再用 Johnson 规则就是最优的。一般情形没有这个性质，下一节用启发式。

11.2三台以上：NEH 启发式

机器多了以后，实际中最常用的构造启发式是 NEH（Nawaz、Enscore、Ham，1983）。它的想法很简单：加工时间大的作业更“难安排”，先安排它们；每个作业都放在当前最合适的位置。

  1. 按总加工时间 Σk pjk 从大到小排出插入次序。
  2. 取第一个作业，形成只有一个作业的部分顺序。
  3. 依次取下一个作业，试着把它插进部分顺序的每一个位置（含最前和最后），用完工时间递推算出每个位置的 Cmax，保留最小的（并列取靠前的位置）。

插入第 k 个作业要试 k 个位置，总共 O(n²) 次评价，n = 100 也只需要几毫秒。它在流水车间的文献里几乎是“必比的基线”，很多更复杂的方法（禁忌搜索、迭代贪心）都以 NEH 的解为起点。

读图

总加工时间是 J1 15、J2 18、J3 15、J4 18、J5 13、J6 19，所以插入次序是 J6、J2、J4、J1、J3、J5（并列取下标小的）。部分顺序的 Cmax 依次是 19、26、29、33、38、44。最后 NEH 得到 J5 → J1 → J4 → J3 → J6 → J2，Cmax = 44；原顺序 J1…J6 是 52；枚举 720 种得到的最优是 42。NEH 一共只评价了 1 + 2 + 3 + 4 + 5 + 6 = 21 个候选，把 52 压到 44，与最优差 2。

它不保证最优。第 5 步插入 J3 时五个候选是 41、40、38、38、42，最小值 38 出现两次，规则取靠前的那个。换一个并列规则，后面的结果可能不同，所以 Lab 的练习 2 把并列规则写死，让结果可以复现。

11.3作业车间与析取图

作业车间（job shop）里，每个作业有自己的路线：作业 J1 先上 M3，再 M2，最后 M1；作业 J2 的路线是 M3、M1、M2。同一台机器一次只做一个作业。记号 Jm | | Cmax。四向车仓库里“每个托盘要经过不同的一串站点”就是这个模型。它比流水车间难得多：流水车间是它的特例，所以 J3 | | Cmax 也是强 NP 难的； 10 × 10 的经典实例（Fisher–Thompson，1963）在提出后二十多年里都没有被证明最优。

用析取图（disjunctive graph）来表示：

  • 节点是工序（作业 j 的第 k 道），节点权重是它的加工时间。
  • 路线弧（实线灰色）：同一作业的相邻工序，前一道做完才能做后一道。
  • 析取弧：同一台机器上的两个工序不能同时做，要么 A 在 B 前，要么 B 在 A 前，这是一个二选一（“析取”）。选定每台机器上的作业顺序，就是为每一对二选一定下方向，得到一张有向图。

一个选择对应一个可行调度，当且仅当这张有向图没有环。有环意味着“A 要等 B，B 要等 C，C 又要等 A”，谁也无法开工。无环时，每道工序的最早开始时刻就是从起点到它的最长路，Cmax 是整张图里的最长路，最长路上的工序叫关键工序，缩短不在关键路径上的工序不会让 Cmax 变小。

析取图求值Cmax = 图中的最长路（按拓扑序一遍扫描），有环则不可行O(工序数 + 弧数)

所以作业车间的搜索空间是“每台机器上的一个排列”，共 (n!)m 个组合，其中一部分带环。

读图

每台机器都按 J1、J2、J3：可行，Cmax = 21，关键路径 J1·M3 → J1·M2 → J1·M1 → J2·M1 → J2·M2 → J3·M2 → J3·M1 → J3·M3，几乎把所有工序串成了一条线。最优：Cmax = 13，三台机器上的顺序分别是 M1：J2、J3、J1，M2：J3、J2、J1，M3：J2、J1、J3；关键路径是 J2·M3 → J2·M1 → J3·M1 → J1·M1，长度 1 + 4 + 5 + 3 = 13。下界（最忙的机器或最长的作业）是 12，最优比它大 1。

有环的例子：M1、M2 上都是 J1、J2、J3，M3 上却是 J3、J2、J1。图里出现红色的环，页面给出具体的环。216 种机器顺序里只有 63 种是可行的，不到三分之一。这个比例在大规模问题里会更小，所以直接在“机器顺序”上做局部搜索时，要小心邻域产生的解是否有环。

需要留意，一个可行的机器顺序对应“半主动调度”：每道工序都尽可能早开始。Cmax 是正规目标（完工时间变晚不会变好），所以最优调度总可以取成半主动的，搜索机器顺序就够了。

11.4两种建模：大 M 的 MIP 与 CP-SAT

同一个作业车间问题，可以写成混合整数规划，也可以写成约束规划（CP）。它们描述的是同一个问题，但求解器的表现差别很大。这一节把两个模型并排放，看差别在哪里。

大 M 的 MIP 模型

变量：每道工序的开始时刻 so，最大完工时间 C，以及同一台机器上每一对工序 (a, b) 的顺序变量 yab ∈ {0, 1}（1 表示 a 在 b 之前）。约束：

路线sj,k+1 ≥ sjk + pjk同一作业的相邻工序
析取sb ≥ sa + pa − M(1 − yab)，　sa ≥ sb + pb − M yaby = 1 时第一条起作用，y = 0 时第二条起作用；另一条被 M 放松
目标min C，　C ≥ sj,末 + pj,末每个作业的最后一道工序

这是第 4 章讲过的“大 M”写法。它的问题也是第 4 章的问题：M 取工序时间之和（一个安全的上界），把 y 放松成 [0, 1] 以后，两条析取约束几乎不起作用，LP 松弛值很小。对本章的 3 × 3 例子，LP 松弛值只有 9.0，而下界是 12、最优是 13。松弛这么弱，分支定界就得枚举大量的 y 组合才能证明最优。

CP-SAT 的模型

CP-SAT 直接支持区间变量和不重叠约束：每道工序是一个区间（开始、时长、结束），每台机器上的区间用一个 NoOverlap 约束，作业内部用 start ≥ 前一道的 end。没有 M，没有 0/1 的顺序变量，求解器内部知道“不重叠”的含义，会做边界推理：比如推断“这几个工序合起来至少占用多长的时间窗”，并把传播的结果学成子句。

表 11-1同一批随机作业车间实例（作业数 × 机器数，每个作业走遍所有机器，加工时间 1–9）上，用 Lab 参考答案实测。MIP 是 SciPy 的 HiGHS，限时 30 秒；CP-SAT 是 OR-Tools，单线程。“MIP 结果”一栏是限时内找到的最好解 / 证明的对偶界。用时依赖机器，只有数量级有参考意义。

读表

3 × 3 时两者都是毫秒级，看不出差别。到 8 × 8（64 道工序），MIP 花了 7.9 秒才证明最优，CP-SAT 只要 0.02 秒。到 10 × 10 和 12 × 10，MIP 在 30 秒内没有证明最优：10 × 10 找到了 52，对偶界只到 42，最优值是 47，还有很大的间隙；12 × 10 找到 57，对偶界 41.57，最优 48。CP-SAT 在同样的实例上都在 0.1 秒内证明了最优。

这个差别来自问题的结构，与 CP-SAT 是否普遍更强无关。作业车间由“不重叠”这种时间窗推理主导，CP 的模型和推理正好对口，MIP 的松弛却被大 M 破坏。反过来，如果问题的主要难点在成本的线性结构上（第 5–7 章的指派、网络流、背包），MIP 的强松弛和切平面才是优势。选择建模语言要看问题的结构，这是本章最重要的一条建议。

最后一个提醒，模型正确不等于模型好用。两个模型的最优值必须相同（Lab 的练习 4 用 pytest 检查这一点），求解速度才是要比的东西。

参考实现（Lab 练习 4）

下面两段代码来自 Lab 的参考答案。第一段构造大 M 模型并交给 HiGHS；第二段是 CP-SAT。

def mip_jobshop(jobs):    """大 M 的析取模型，返回最优的最大完工时间（整数）。"""    c, A, lo, hi, n, npair, M = _mip_parts(jobs)    integrality = np.zeros(len(c))    integrality[n + 1:] = 1    ub = np.concatenate([np.full(n + 1, M), np.ones(npair)])    res = milp(c, constraints=LinearConstraint(A, lo, hi), integrality=integrality, bounds=Bounds(np.zeros(len(c)), ub))    return int(round(res.fun))
def cp_jobshop(jobs):    """CP-SAT：区间变量 + 每台机器的 NoOverlap，返回最优的最大完工时间。"""    from ortools.sat.python import cp_model    model = cp_model.CpModel()    horizon = sum(d for job in jobs for _, d in job)    by_machine = {}    ends = []    for j, job in enumerate(jobs):        prev_end = None        for k, (m, d) in enumerate(job):            s = model.NewIntVar(0, horizon, f"s{j}_{k}")            e = model.NewIntVar(0, horizon, f"e{j}_{k}")            iv = model.NewIntervalVar(s, d, e, f"i{j}_{k}")            by_machine.setdefault(m, []).append(iv)            if prev_end is not None:                model.Add(s >= prev_end)            prev_end = e        ends.append(prev_end)    for ivs in by_machine.values():        model.AddNoOverlap(ivs)    cmax = model.NewIntVar(0, horizon, "cmax")    model.AddMaxEquality(cmax, ends)    model.Minimize(cmax)    solver = cp_model.CpSolver()    solver.parameters.num_workers = 1    solver.parameters.random_seed = 1    status = solver.Solve(model)    assert status == cp_model.OPTIMAL    return int(solver.ObjectiveValue())

11.5在项目里的位置

这一章的模型和四向穿梭车仓库的对应关系很直接，但直接套用之前要先想清楚哪些假设不成立。

对应关系

  • 入库口 → 提升机 → 出库口：一批托盘依次经过三个设备，设备一次只处理一个托盘，正好是 F3 | | Cmax。作业顺序由“先处理哪个托盘”决定，NEH 可以直接当作离线排序的基线。
  • 托盘走不同的路线：有的托盘要过提升机换层，有的不用；有的要经过分拣站，有的不用。这就是作业车间，路线不同，机器（设备）可以被多个作业竞争。
  • 小规模精确，大规模换方法：几十道工序以内，CP-SAT 可以证明最优，也可以做在线滚动求解；工序数上千以后，需要第 5、6 部分的分解和启发式。

要小心的假设

  • 缓冲区是有限的：经典流水车间假设两台机器之间有无限缓冲，作业做完后可以等着。真实的提升机前只能停几个托盘，满了上一站就被阻塞（blocking）。有限缓冲的流水车间没有 Johnson 规则，要另外建模。
  • 没有转换时间：换层、换向的时间与前后的作业有关（序相关的准备时间），第 9 章的 sjk 就是这个。带上它，即使一台机器也是 TSP 型的难问题。
  • 作业一开始就全部就位：Cmax 的排序适合“一个波次的所有托盘已知”，托盘陆续到达时要用滚动时域，或者改用 11.4 的 CP 模型每隔一段时间重新求解。

Lab 的挑战是一个最常用的派工规则（dispatching rule）：每次在所有“可以开始”的工序里，选最早能开始的一道，并列时选加工时间短的。它算得很快，但在本章的 3 × 3 例子上得到 15，最优是 13。规则给出的是可行解，而不是最优解，把它当作 CP-SAT 的初始解或者对照基线是合适的。

11.6小结与 Lab

  1. 流水车间：所有作业走同样的机器次序，置换调度的 Cmax 由递推 Cjk = max(Cj−1,k, Cj,k−1) + pjk 在 O(nm) 内算出。
  2. F2 | | Cmax：Johnson 规则，a ≤ b 的按 a 升序放前面，a > b 的按 b 降序放后面，最优。第 3 台机器加入后就是强 NP 难。
  3. NEH：按总加工时间降序，逐个插到使部分顺序 Cmax 最小的位置。只评价 O(n²) 个候选，通常很接近最优，但没有最坏保证。
  4. 作业车间：析取图上，节点是工序，路线弧固定，选定每台机器的作业顺序即为析取弧定向。Cmax 是最长路，有环即不可行。3 × 3 的例子里，216 种机器顺序只有 63 种可行。
  5. 同一个问题的两种模型：大 M 的 MIP 松弛很弱（本章例子 LP 值 9.0，最优 13），规模一大就证明不了最优；CP-SAT 用区间变量和 NoOverlap，10 × 10、12 × 10 都能在 0.1 秒内证明最优。
  6. 选建模语言要看结构：时间窗和“不重叠”的问题适合 CP，成本线性、网络结构强的问题适合 MIP。
  7. 在项目里，入库 → 提升机 → 出库是 F3，多路线的托盘是作业车间；有限缓冲、准备时间和陆续到达都会改变结论，需要另外建模。
