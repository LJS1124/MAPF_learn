6.3最大流与最小割

最短路只关心一辆车怎么走。现在换一个问题：这张网络一个时间窗最多能送多少？每条弧现在的第一个数是容量：单位时间内最多通过多少辆车、多少托盘。

一个流给每条弧分配一个流量 xuv，要求 0 ≤ xuv ≤ 容量，并且除了 S 和 T 之外，每个点流入等于流出（流量守恒）。流量 = 从 S 净流出的量。最大流问题就是让它最大。

增广路与回退弧

从零流开始，反复做一件事：在残量图里找一条 S 到 T 的路，沿着它推流。残量图对每条原弧有两个方向：

前向残量

容量 − 已用流量。还能往前推多少。

回退弧

已用流量。可以把已经送出去的流量收回来多少。推流经过回退弧，等于减少原弧的流量。

瓶颈

路径上残量的最小值。沿路推这么多，恰好有一条弧变满（或者一条回退弧被收空）。

回退弧是最大流里最容易被忽略的部分。没有它，贪心地找路推流可能卡在一个不是最大的流上：先推的那条路占了一条关键的弧，别的路就被堵死了。回退弧允许后来的路说“这条弧先借我，我的流量从别处补给你”。Lab 练习 5 里有一个 AI 写的函数就是漏了这一步。

选路的规则也有讲究。随手选一条路（比如深度优先）可能要推很多次；每次选边数最少的路（宽度优先），就是 Edmonds–Karp 算法，增广次数不超过 n m / 2，总时间 O(n m2)，与容量的大小无关。

读图

最短增广路：4 次。先走 S→a→c→T 推 4，再走 S→a→d→T 推 2，然后 S→b→c→T 推 2，最后 S→b→d→T 推 4，一共 12。它们互不干扰，没有用到回退弧。

随手选：8 次，其中一半用到回退弧。深度优先先钻进 S→a→b→c→d→T 这条弯弯绕绕的路，只推了 2，就把 b→c 用满了；后面的路不得不反复把流量退回来重新分配。最终值同样是 12，只是绕了远路。最坏情况下，随手选的次数可以随容量变大而增加，最短增广路的次数只取决于网络的大小。

最大流等于最小割

算法停下来的时候，残量图里已经没有 S 到 T 的路。把从 S 还能到达的点记作 X，其余记作 Y（包含 T）。所有从 X 到 Y 的原弧都是满的（否则那里还有残量，Y 里的点就到得了），所有从 Y 到 X 的原弧流量都是 0（否则有回退弧）。于是流量恰好等于 X 到 Y 那些弧的容量之和，这叫割的容量。

最大流最小割定理（Ford–Fulkerson，1956）

最大流量 = 所有割中最小的容量。

任何流都得穿过任何一个割，所以流量 ≤ 割容量，这是“弱”的一半，一行就能证。算法停下来时构造出一个流量等于割容量的流和割，这是“强”的一半。

整数性

容量全是整数时，最大流也可以取整数：每次瓶颈是整数，每次推流都是整数。

这一点在 6.5 节用全单模再证一遍，而且会推广到最小费用流。

图 6-2 的最后一步给出的割是 {S, a, b} 对 {c, d, T}，割边是 a→c、b→c、b→d、a→d，容量 4 + 2 + 4 + 2 = 12。这个割就是瓶颈的位置：想让窗口多放行车辆，只有给这四条弧扩容才有用，加宽 S→a 或 d→T 没有任何效果。做规划时这是一个很实用的结论：最小割告诉你该在哪里投资。

最小割还是最大流的证书：拿到一个流和一个割，两个数相等，就不必相信算法，直接检查即可。Lab 练习 2 要求同时返回流和割；练习 5 里有一个 AI 写的函数，流是对的，报出来的割却不是最小的。

6.4最小费用流

最大流只管送得多。真实问题里每条弧还有单价：走不同的通道费用不同。送 k 个单位，怎么送最便宜？这就是最小费用流，它把最短路和最大流合成了一个问题。

做法直接：逐次最短路。每一轮在残量图上找 S 到 T 的最短路（按费用，不按边数），沿它推瓶颈流量。回退弧的费用是原弧费用的相反数，走回退弧等于把之前的一部分流量撤销，还退回它当时花的钱。

回退弧带来负费用，Dijkstra 不能直接用。办法就是 6.2 节的势：维护一组势，让残量图里每条弧的约化成本 c + h(u) − h(v) 都 ≥ 0；每一轮 Dijkstra 之后，把每个点的势加上它的最短距离。新增的回退弧恰好落在最短路上，约化成本为 0，所以不变量保持。这和第 5 章的“涨价”是同一个动作。

读图

边际成本逐级上涨：7、7、7、7、8、8、9、9、9、9、10、10。最便宜的通道 S→b→d→T 单价之和是 7，但 b→d 的容量只有 4，四个单位之后它就满了。下一批走 S→a→d→T，单价 8，只有 2 个单位；再下一批走 S→a→c→T，9；最后 S→b→c→T，10。总费用 4×7 + 2×8 + 4×9 + 2×10 = 100。

费用曲线是凸的。逐次最短路每一轮的路都不比上一轮短：便宜的通道先被用光，剩下的只会更贵。所以 f(k) 是分段线性的凸函数，斜率不降。这对定价有直接含义：送得越多，多送一个单位的成本越高，“平均成本”会低估“边际成本”。

势就是对偶价格。勾选“显示势”，每个点旁边的 h 是当前的势。残量图里所有弧的约化成本都 ≥ 0，这就是最优性证书，与第 2 章“对偶变量给出最优性证明”、第 5 章“价格可行且边是紧的”是同一件事。Lab 练习 3 要求返回这组势，由判分程序独立检查。

送 n 个单位的最小费用流，就是最优的指派。逐次最短路的每一轮，对应第 5 章“新任务到达时沿一条改派链调整”：残量图里从源出发的最短路，经过“车→任务”的正向弧和“任务→车”的回退弧交替前进，正是那条改派链；这一轮的路长，就是第 5 章的边际成本。第 5 章的匈牙利算法可以看成把这个通用算法特化到二部图上，价格和势合并成两组。

把中间的容量从 1 改成别的数，得到运输问题：多个仓库供货，多个门店需求，每条线路有容量和单价。四向车与提升机的场景里，提升机可以看成一条容量有限的弧（6.7 节会讲怎么处理“点的容量”）。这些问题都能用同一份代码解决。Lab 练习 4 让你把指派写成网络，再调用练习 3 的算法验证 124 s。

另一条路：循环取消先随便造一个满足流量的流（不从零流出发），再检查残量图里有没有负费用的环。有的话，沿环推流，总费用严格下降；没有，就是最优。“残量图没有负环”与“存在一组使所有弧约化成本 ≥ 0 的势”是同一个条件的两种说法（6.2 节：有势当且仅当无负环）。Lab 挑战让你实现这个算法，并和逐次最短路对拍。

6.5网络矩阵为什么不需要分支

前面三节的算法都是组合式的，没有一处用到 LP。可是最大流、最小费用流同样能写成 LP，而且直接给整数解。第 5 章证明过指派矩阵是这样，这一节把同样的证明用到整个网络。

把网络的约束写成矩阵。设网络有 n 个点、m 条弧，点弧关联矩阵 A 有 n 行 m 列：弧 (u, v) 对应的那一列，在 u 行是 +1，在 v 行是 −1，其余全是 0。

流守恒A x = b,　0 ≤ x ≤ ub 在 S 处是 +k，在 T 处是 −k，其余是 0
定理

点弧关联矩阵 A 全单模。

证明与第 5 章的引理一模一样，只有三步。

推论（整数性）

容量 u 和流量 k 都是整数，则 {x : A x = b, 0 ≤ x ≤ u} 的每个顶点都是整数点。

加上单位矩阵（上下界）之后仍全单模。所以最大流、最小费用流、最短路、指派、运输，全都是“LP 就是整数问题”。

  1. 取 A 的任意一个 k×k 子矩阵 B。对 k 归纳；k = 1 时元素是 0、±1。
  2. 若 B 有一列全为 0，行列式为 0。若有一列恰好一个非零元素（±1），按这一列展开，行列式是 ± 一个 (k−1) 阶子式，由归纳假设是 0 或 ±1。
  3. 否则 B 的每一列都恰好有两个非零元素。A 的每一列只有一个 +1 和一个 −1，所以 B 的这两个元素也必然是一个 +1 加一个 −1。把 B 的所有行加起来，得到零向量，行线性相关，行列式为 0。

整个论证只用了一件事：每一列恰好一个 +1 和一个 −1，也就是“每条弧有一个起点和一个终点”。第 5 章的指派矩阵是二部图的特例，行分两组，每列在两组里各有一个 1。这里的写法更一般：不需要分组，只需要每列正负各一。

这带来两个实用的结论。第一，单纯形法不需要分支：无论是直接用 LP 求解器，还是用 6.4 节的组合算法，得到的最优解都是整数流。第二，对偶变量也是整数：费用是整数时，势（对偶变量）也取整数，这解释了为什么本章所有势都是整数，也解释了最大流最小割定理里的割是 0/1 的。

读图

不加行：6 个点 × 10 条弧的矩阵，方子式共 8007 个，行列式只有 0、+1、−1 三种，全单模，和证明一致。拖动 k，LP 的解始终是整数，值与图 6-3 的费用曲线完全一样。

点 c 的容量：“进入 c 的两条弧合计至多 4”。这一行同样是全单模，因为点容量可以通过拆点还原成弧容量：把 c 拆成入口和出口，中间加一条容量为 4 的弧。所以点的容量限制不需要担心整数性。提升机一次只能过一辆车，就是这样处理的（6.7 节）。

串联弧共限额：“S→b 与 b→d 合计至多 1”。这一行把两条首尾相接的弧绑在一起，检查器在多了一行的矩阵里找到行列式 ±2 的方子式。取 k = 1：最便宜的路 S→b→d→T（费用 7）会占用这个限额两次，超了；整数解只好走 S→a→d→T，费用 8。LP 却可以让 ½ 单位走 S→b→d→T、½ 单位走 S→a→d→T，两条弧合计只用了 ½ + ½ = 1，费用 7.5。差的 0.5 就是整数性的代价，只有分支才能消除。

另一处共限额是同样的结构，出现在 k = 7 和 8：LP 53.5，整数最优 54。注意不是每个 k 都会有差距，全单模的意思是“保证”，失去保证不等于每次都出问题。

网络可以加什么，不可以加什么可以：弧的上下界、点的容量（拆点）、多个源和多个汇（加一个超级源和超级汇）。不可以：把两条不同的弧绑在同一个限额里（尤其是首尾相接的弧）、要求某个点的流入必须来自“同一种”货物。前者破坏“每列一个 +1 一个 −1”的结构，后者是下一节的多商品流。
