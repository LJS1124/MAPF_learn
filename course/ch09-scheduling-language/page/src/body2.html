9.4机器环境：有几台，怎么配

机器不止一台的时候，先要分清机器之间是什么关系。

并行机：一个作业只在一台机器上做一次

P（相同）：加工时间与机器无关。Q（速度不同）：机器 i 的速度是 si，时间是 pj / si。R（不相关）：pij 是任意的一张表，机器各有所长，比如不同位置的四向车做同一个任务的行驶时间。

车间：一个作业要依次经过几台机器

F 流水车间：所有作业经过机器的顺序相同（入库 → 提升机 → 出库）。J 作业车间：每个作业有自己的路线。O 开放车间：作业要在每台机器上做，顺序不限。第 11 章展开。

P、Q、R 越往后越一般：P 是 Q 的特例（所有速度为 1），Q 是 R 的特例（pij = pj / si）。这个“特例关系”后面用来推理复杂度。

读图

单机：Cmax = 30，总加工时间，顺序无关。两台相同的机器：总量 30，下界 15。按编号列表调度得到 16，最优是 15；改成“最长的先放”（LPT）就得到 15。列表调度是一种很快的启发式，但它没有保证一定最优，即使是最简单的 P2 || Cmax，它也是一个 NP 难的问题（由划分问题推出）。

两台不相关的机器：按编号列表调度恰好是最优（11）；换成“最长的先放”，得到 14，比最优多 3。顺序策略对不同环境的效果不同，没有哪一条规则永远最好，所以要知道问题是哪一类，才能知道该用哪种方法。

9.5复杂度地图：哪些容易，哪些难

调度领域积累了几百个问题的复杂度结果。你不需要背，只需要理解推理规则：一个问题至少和它的特例一样难，至多和它的推广一样容易。

  1. 特例与推广：1 是 P 的特例，P 是 Q 的特例，Q 是 R 的特例；没有释放时间是有释放时间的特例；Cmax 是 Lmax 的特例（令 dj = 0）；ΣCj 是 ΣwjCj 的特例（令所有 wj = 1）。
  2. 难度沿推广传播：如果 A 是 NP 难的，B 是 A 的推广，B 也是 NP 难的。因为解 B 的算法可以拿来解 A。
  3. 容易沿特例传播：如果 B 有多项式算法，A 是 B 的特例，A 也有。
  4. 但可中断（prmp）不在这个序里：允许中断可能让问题变容易，也可能没有影响，不能靠它推理。

“NP 难”也有强弱：弱 NP 难的问题有伪多项式时间的算法（数值不大时可以用，比如动态规划），强 NP 难的问题连这样的算法也没有（除非 P = NP）。图 9-3 里橙色是弱 NP 难，红色是强 NP 难或没有区分。

读图

先看 β 为空的地图：单机（第一行）上，目标几乎全是多项式可解的：Cmax、ΣCj、ΣwjCj、Lmax、ΣUj 都有简单的规则。往下走，机器变多，绿色越来越少：P2 的 Cmax 已经是 NP 难（划分问题）。同一个机器环境里，目标不同，难度也可以完全不同：R || ΣCj 是多项式的（它就是第 5 章的指派问题），R || Cmax 却是强 NP 难。

再加 β：点亮 rj（释放时间）。单机的 Lmax、ΣCj 立刻变成红色：没有释放时间时 EDD、SPT 一步到位，一旦作业陆续到达，问题就变成强 NP 难。这个变化对系统很重要：任务动态到达，会让原本简单的排序问题变难，也是第 30 章在线调度的出发点。

复杂度地图的用法遇到一个调度问题，先写出它的三段式标签，查地图。绿色：找对应的规则或算法，不要建 MIP。橙色：数值不大时用动态规划。红色：用 MIP 或约束规划（第 11 章）求解小规模，用启发式（第 21 章）求解大规模，并用下界评价解的质量。

9.6在项目里的位置

把你场景里的设备翻译成三段式标签，是这一部分每一章开始前要做的事。

场景记号难度与做法
一台提升机，托盘排队，尽量减少平均等待1 | | ΣCj（或带权重 ΣwjCj）多项式：SPT / WSPT（第 10 章）

其中最后一项提醒：三段式记号覆盖的是经典模型。真实系统里的约束（时间窗、共享资源、设备之间的互斥）往往超出记号，这时它的价值是让你说清“最接近的经典问题是什么”，然后知道自己在它的基础上加了什么、复杂度大致会怎样变化。
